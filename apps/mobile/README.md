## Getting Started ðŸš€

This project contains 3 flavors:

- development
- staging
- production

To run the desired flavor either use the launch configuration in VSCode/Android Studio or use the following commands:

```sh
# Development
flutter run --flavor development --target lib/main_development.dart

# Staging
flutter run --flavor staging --target lib/main_staging.dart

# Production
flutter run --flavor production --target lib/main_production.dart
```

_This project works on iOS, Android, Web, and Windows._

## Android Release

This project uses custom Flutter entrypoints per flavor, so for Android release builds use the explicit `--flavor` and `--target` commands instead of the generic Android Studio Flutter build actions.

### Generate the upload keystore

```powershell
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v `
  -keystore C:\Workspace\APPS\keystores\tcg-platform-mobile.p12 `
  -storetype PKCS12 `
  -keyalg RSA `
  -keysize 4096 `
  -validity 10000 `
  -alias key0
```

Then configure `android/key.properties` with:

- `storePassword`
- `keyPassword`
- `keyAlias`
- `storeFile`

`storeFile` should point to the generated `.p12` file.

### Generate the production app bundle

```powershell
flutter build appbundle --release --flavor production --target lib/main_production.dart
```

### Generate production APKs split by ABI

```powershell
flutter build apk --release --split-per-abi --flavor production --target lib/main_production.dart
```

Typical outputs:

- `build/app/outputs/bundle/productionRelease/`
- `build/app/outputs/apk/production/release/`
- `build/app/outputs/flutter-apk/`

## iOS Release

For iOS release builds on macOS, use the terminal from VS Code from the project root and let Flutter prepare the iOS project before opening Xcode.

### 1. Clone the repository and open it in VS Code on macOS

Open the project root and use the integrated terminal.

### 2. Check the Flutter environment

```bash
flutter doctor
```

### 3. Download dependencies

```bash
flutter pub get
```

### 4. Run the production flavor once

```bash
flutter run --flavor production --target lib/main_production.dart
```

This first run is important because Flutter may automatically migrate and prepare the iOS project, including Xcode compatibility updates and Swift Package Manager integration.

### 5. Open the iOS workspace in Xcode

```bash
open ios/Runner.xcworkspace
```

### 6. Review signing and Apple configuration in Xcode

In Xcode, review:

- `Signing & Capabilities`
- Apple `Team`
- app version
- the `production` scheme selected at the top

### 7. Archive, validate, and upload from Xcode

In Xcode:

- `Product > Archive`
- `Validate App`
- `Distribute App / Upload`

### 8. Commit the iOS configuration changes

After the first successful iOS run/migration, review the generated iOS configuration changes and commit them to the repository.
